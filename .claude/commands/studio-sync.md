description: 짝 Studio 싱크 — 싱크 대장의 보류 항목(또는 적어 준 변경)을 반대쪽 Studio 에 옮기고 70 로컬 배포까지
---

사용자가 `/studio-sync` 를 입력했다. 인자 `$ARGUMENTS`:
- **비어 있음** → 대장의 보류 전체를 추천(도입 / 해당 없음)과 함께 보여 주고, 무엇을 옮길지 **한 번만** 묻는다.
- **번호**(`1 2 3`) 또는 `all` → 묻지 않고 그 항목을 옮긴다. 비고에 '사용자 결정' 이라 적힌 항목은 `all` 에서 빼고 따로 묻는다.
- **글**(예: `MB 0.1.9 힘 라벨을 MU 에도`) → 대장에 없는 변경이다. 대장에 줄을 먼저 만들고 옮긴다.

규칙·대장·절차 원본 = `docs/standards/studio-pair-sync.md` — **먼저 읽는다.** 여기는 순서만 적는다.
이 명령은 옮긴 Studio 의 **70 로컬 배포(버전 올리기·zip·핀 동기화)까지** 요청한 것이다. 145 공개(`/studio-release`)와 커밋·푸시는 하지 않는다.

## 1. 상태 확인 (옮기기 전에)
- `python scripts/studio_pair.py` — `SAME_MISMATCH` 가 0 이 아니면 그것부터 맞춘다.
- **옮길 쪽 Studio 에 다른 작업이 진행 중인지** 본다: 그 저장소 `git status --short` 와 최근 30분 안에 고쳐진 소스.
  있으면 멈추고 알린다 — 다른 세션과 같은 파일을 덮어쓰거나 버전이 겹친다. 사용자가 그래도 하라고 하면 진행한다.
- 출발 쪽 변경이 145 에 공개된 것인지 본다(`HiTessWorkBenchBackEnd/app/studio_release.json` 의 버전). 70 로컬에만 있는 변경은 아직 바뀔 수 있다 —
  사용자가 번호·글로 직접 짚었으면 그대로 하고, 인자 없이 불렀으면 추천에서 '공개 뒤에' 로 미룬다.

## 2. 옮길 것 정하기
- 대장에서 판정이 **보류** 인 줄 + 검사의 '바뀜' 목록(아직 대장에 없는 것은 줄을 만든다).
- 항목마다 출발 쪽 구현을 읽고 판정을 추천한다: **도입**(옮길 쪽에도 같은 화면·같은 문제가 있다) / **해당 없음**(그 Studio 에만 맞는 변경 — 이유 한 줄).
- 이 명령으로 옮기지 않는 것 — 보류로 두고 이유를 알린다:
  새 편집 intent 가 필요한 변경(MB 는 C# 엔진·계약 테스트가 따라온다. MU 는 Studio 가 JS 로 적용) · 백엔드나 Electron 변경이 함께 필요한 것 · 사용법이 달라지는데 사용자 결정이 없는 것.

## 3. 옮기기
- 출발 쪽 코드를 옮길 쪽 구조에 맞게 넣는다. 파일을 **같은 내용으로** 둘 수 있으면 그대로 복사하고 `scripts/studio_pair.json` 의 `same` 에 올린다.
- 화면에 보이는 것이 바뀌면 그 Studio 의 도움말(`data/helpContent.js`·`data-help`)도 맞춘다. 사용 설명서에 닿으면 보고에 적는다(설명서 갱신은 따로 요청받아 한다).
- 출발 쪽 Studio 는 고치지 않는다(같은 내용으로 맞추려고 양쪽을 다 고쳐야 하면 먼저 알린다 — 출발 쪽도 버전·배포가 따라온다).

## 4. 확인
- 옮긴 Studio 폴더에서 `npm test` · `npm run lint` · `npm run build`. 실패하면 배포하지 않고 보고한다.
- `python scripts/studio_pair.py` — `SAME_MISMATCH=0`.
- 화면은 `/shot`(헤드리스 Chrome)으로 볼 수 있으면 보고, 못 보면 '눈으로 확인 안 함' 으로 적는다.

## 5. 기록
- 대장에서 그 줄의 판정을 **도입함**(옮긴 Studio 버전) 또는 **해당 없음**(이유)으로 고친다.
- 닫은 파일은 `python scripts/studio_pair.py --ack <경로> […]`. 보류로 남긴 것은 닫지 않는다.

## 6. 배포 (70 로컬)
- `/deploy` 스킬 `studio.md` 절차대로: 버전 올리기 → `npm run package` → 70 로컬 `StudioProgram\` → 핀 동기화.

## 7. 보고 (짧게)
- 옮긴 항목(번호·한 줄) · 해당 없음으로 닫은 항목(이유) · 보류로 남긴 항목(이유)
- 옮긴 Studio 새 버전, 테스트·lint·빌드 결과, 화면 확인 여부
- 다음: 사용자가 70 에서 화면 확인 → `/studio-release <id>` 로 145 공개. 커밋 필요 저장소(Studio · WorkBench 의 대장·지문·핀).
