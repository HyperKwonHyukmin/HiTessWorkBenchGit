Overview

Module Unit 앱은 BDF 기반 모듈 모델을 3D로 확인하고, 권상 노드/그룹을 지정한 뒤 자세 안정성 평가와 권상 위치 추천 결과를 JSON으로 산출하는 WorkBench용 해석 앱입니다.

ViewerReact + Three.js
Engine.NET 8 CLI
ResultStability JSON
1
모델 JSON 폴더 로드ModuleUnitStudio가 JSON 파일들을 읽어 stage, node, element, mass, COG 정보를 화면에 표시합니다.
2
권상 조건 설정Hydro(Hook), Goliat(Trolley), Ceiling(Crane) 방식과 wire length, 권상 그룹/노드를 지정합니다.
3
편집/저장필요하면 모델 편집 intent를 적용하고 _edited.json, _posture.json 입력 세트를 준비합니다.
4
안정성 평가ModuleAnalysis.Cli.exe가 _posture.json을 받아 Stage 0~6 평가를 실행합니다.
5
결과 표시_stability.json 또는 _hoist_optimization.json을 Studio가 읽어 와이어, 정점, 이슈, PASS/WARN/FAIL을 시각화합니다.
6
구조해석(선택)자세안정성이 PASS/WARN 이면 Analyze 탭에서 Wire 포함 BDF + Nastran SOL 101 구조해석을 실행해 부재 허용응력 초과 여부를 확인합니다. FAIL(허용응력 초과) 이면 가서포트(보강 부재)를 추가하거나 권상점을 다시 잡아 재해석합니다. 자세한 내용은 구조해석(Nastran) 참고.

참조 소스는 C:\Coding\WorkBenchSubModule\ModuleUnitStudio와 C:\Coding\WorkBenchSubModule\ModuleUnitAnalysis입니다. WorkBench 본체에는 임베드/실행 연결부만 두고, 도메인 로직은 두 하위 프로젝트를 기준으로 추적합니다. 단, 구조해석(Nastran SOL 101) 파이프라인 자체는 C# 엔진이 아니라 WorkBench 백엔드(Python)의 unit_structural_service.py가 nastran_bridge.py(InHouseProgram/NastranBridge)와 외부 MSC Nastran을 직접 호출해 수행합니다 — Stage 0~6 자세안정성 평가(C# CLI)와는 별개 엔진입니다.

사용 절차

사용자 관점의 흐름은 모델 확인, 권상점 선택, 평가 실행, 결과 조치입니다.

  1. WorkBench 카드 메뉴에서 ModuleUnitStudio 또는 해당 권상 구조 해석 앱으로 진입합니다.
  2. 자동 주입 폴더가 있으면 즉시 모델을 로드하고, 없으면 "폴더 열기"로 JSON 폴더를 선택합니다.
  3. 3D 뷰어에서 beam, rigid, weld, U-bolt, mass, COG, node 위치를 확인합니다.
  4. 권상 모드와 wire length를 정하고, 그룹별 lug node를 선택합니다.
  5. 자동 권상 위치 추천이 필요하면 최적화 실행을 먼저 돌려 후보 그룹/노드를 비교합니다.
  6. 최종 권상 조건을 저장해 _posture.json과 연결된 _edited.json 입력을 확정합니다.
  7. 안정성 평가 실행 후 결과 패널에서 치명 이슈, 경고, 통과 항목, 와이어 시각화를 확인합니다.

평가 Pipeline

Stability 평가는 _posture.json과 _edited.json으로부터 7개 Stage를 순차 실행합니다. Stage 4·5는 경고만 만들고, 전체 FAIL은 Stage 1·2·3·6에서 결정됩니다.

Stage클래스주요 처리판정
0Stage0_InputParserschema, edited 파일 존재, node 좌표, mass source, mode, group/node 수, wire length를 검증합니다.내부 검증
1Stage1_LiftingShapeClassifierHook/Trolley/Crane 방식과 노드 개수 조합을 확인하고 2점/3점/4점 형상을 분류합니다.FAIL 가능
2Stage2_LiftingShapeVerifier4점 사각형 Z단차, 평면도, convex, Trolley 단변, 3점 삼각형 최대 내각을 검증합니다.FAIL 가능
3Stage3_LiftingApexCalculator정점을 centroid + (0, 0, wireLengthMm)로 계산하고 Trolley 4점은 ±450mm로 분할합니다.wireLength 오류 시 FAIL
4Stage4_SlingAngleInspector각 와이어가 수평면과 이루는 각도를 계산하고 60도 이상인지 확인합니다.WARN만
5Stage5_WireInterferenceInspector와이어 선분과 구조 element 선분 사이 최단거리를 계산해 단면 최대치보다 가까운 간섭을 찾습니다.WARN만
6Stage6_PostureStabilityInspector정점의 XY 지지 영역과 COG 투영점을 비교해 전도 위험을 평가합니다.FAIL 가능

평가 결과

결과 JSON은 화면 카드와 3D overlay가 그대로 읽을 수 있도록 stage별 상세, 사용자 요약, visualization 데이터를 함께 포함합니다.

필드내용화면 사용처
metaschema, phase, sourceFiles, unit, engineVersion, generatedAt결과 파일 식별, 버전 추적
inputliftingMode, wireLength, totalMass, COG, BBox, groups결과 패널의 입력 조건 요약
stagesStage 0~6의 status, summary, results, geometry, conflicts상세 카드, 단계별 진단, 근거 metrics
visualizationapexes, wires, wire angle, safe/warn 상태3D 와이어 overlay와 안정성 시각화
overall종합 status, highestSeverity, stageStatuses, userSummary, issueSummary최상단 PASS/WARN/FAIL, 핵심 조치 메시지
  • overall.status = pass: 치명 이슈와 경고가 없는 상태입니다.
  • overall.status = warn: Stage 4 슬링각 또는 Stage 5 와이어 간섭 등 검토 항목이 있지만 형상/전도 FAIL은 없습니다.
  • overall.status = fail: Stage 1·2·3·6 중 하나가 실패했으며 현재 권상 조건으로 진행하기 어렵습니다.
  • overall.userSummary.criticalIssues는 사용자가 먼저 수정해야 하는 문제를 headline, message, impact, action으로 제공합니다.
  • visualization.wires[].angleDeg와 safe는 viewport 와이어 색상/상태 표시의 기준입니다.

구조해석(Nastran)

자세안정성이 PASS/WARN 이면 Analyze 탭에서 Wire 포함 BDF 를 생성해 Nastran SOL 101 로 부재 응력을 계산하고, 허용응력(안전율 반영) 초과 여부를 평가합니다. Stage 0~6 파이프라인과 달리 C# CLI 가 아니라 WorkBench 백엔드(Python)가 직접 수행합니다.

단계구현내용
0. 편집 모델 동기화useUnitStructuralRunner.js syncEditedModel()가서포트 등 편집 intent 가 있으면 실행 직전 _edited.json을 백엔드에 재업로드합니다(host.uploadEvaluationArtifact).
1. Wire 포함 BDF 생성unit_structural_service.py → nastran_bridge.py lift-run --prepare-only_edited.json(있으면) 또는 원본 BDF 로부터 _lifting.bdf + _lifting_meta.json 생성.
2. Nastran SOL 101 실행subprocess.run([nastran_exe, lifting_bdf, "scr=yes", "old=no", "batch=no"])외부 MSC Nastran(NASTRAN_EXE 환경변수로 override 가능)이 _lifting.f06을 생성합니다. 타임아웃 30분.
3. 결과 매핑nastran_bridge.py lift-result --allowable-mpaF06 → _lifting_nastranResult.json(부재별 응력, memberExceedCount 등 summary).

가서포트(임시 보강 부재)

허용응력을 초과하면 권상점을 다시 잡거나, 노드 2개를 Shift+Click 으로 선택해 보강 부재(가서포트, addSupportBeam intent)를 추가한 뒤 재해석할 수 있습니다. 추가/제거 모두 useUnitStructuralStore.reset()을 호출해 이전 구조해석 결과를 자동 무효화하므로, 이 반복(추가→재해석)은 별도 초기화 없이 여러 번 수행할 수 있습니다.

재해석 반복 시 주의(2026-07-07 수정 반영)

구조해석이 한 번 완료(Success)되면 useUnitStructuralRunner.js의 isFinished 가드가 Run 버튼을 잠급니다("해석 완료 — 초기화 후 재실행"). 과거엔 권상점을 다시 잡아 재평가하는 경로에서 이 잠금이 풀리지 않아 사이드바 전체 초기화(가서포트·편집 소실)를 강요했습니다. 지금은 useEditStore.js의 resetHoistPoints()와 exportPostureStabilityToFile()(자세안정성 재평가) 가 useUnitStructuralStore를 함께 무효화하도록 수정되어, 권상점 재선정 → 재평가 → 재해석 루프도 가서포트 루프처럼 초기화 없이 반복할 수 있습니다. 백엔드도 재실행 시 {stem}_lifting.* 전체(이전 .op2/DB 포함)를 정리하고 scr=yes old=no로 Nastran 을 호출해 반복 실행 중 stale DB 로 인한 실패를 방지합니다.

Workbench 연동

Studio는 WorkBench Electron 내부에서 임베드될 수 있도록 host adapter 계약을 사용합니다.

API호출 방향역할
pickFolder()Studio -> WorkBench사용자가 폴더를 직접 선택하면 WorkBench main process가 모든 JSON 파일을 읽어 반환합니다.

연동 검증

  • Workbench에서 Studio 화면이 열리고 빈 화면/콘솔 에러가 없는가?
  • 자동 폴더 주입으로 JSON stage가 로드되는가?
  • "폴더 열기" 수동 경로가 Electron dialog로 정상 동작하는가?
  • 권상 조건 저장 후 _posture.json과 _edited.json이 같은 작업 폴더에서 서로 참조되는가?
  • CLI 실행 후 _stability.json 결과가 Studio 결과 패널과 3D overlay에 표시되는가?
  • 자세안정성 PASS/WARN 후 구조해석을 실행하면 _lifting_nastranResult.json이 생성되고 부재 초과 summary 가 결과 패널에 표시되는가?
