## Anti-Patterns Verdict

**AI가 만든 것처럼 보이는가: 아니다.** 그라데이션 텍스트·대문자 eyebrow·동일 카드 그리드·hero-metric 템플릿 어느 것도 없다. 문제는 반대 방향이다 — 디자인 시스템 없이 손으로 쌓아 올린 인라인 스타일 더미다. Tailwind·shadcn이 의존성에 설치돼 있지만 `className`은 전체에서 3회뿐이고 `style={{}}`이 716회다.

**결정론적 스캔** (`detect.mjs`, 8건 · 전부 warning):
- `side-tab` ×2 — **절대 금지 항목 적중**. `InputAuditPanel.jsx:212`(표 행 `borderLeft: 3px`), `LayerPanel.jsx:169`(항목 `borderLeft: 3px`)
- `layout-transition` ×6 — 진행바의 `transition: width`. 진행바는 정당한 용도라 대부분 오탐에 가깝지만 `transform: scaleX`가 더 매끄럽다

**detector가 못 잡은 것 중 실측으로 확인한 것**: 라이트 모드 대비 실패 52건(최악 1.27:1), 다크 모드 27건, 8px 텍스트 8곳, `:focus` CSS 규칙 0개, `h1~h6` 0개, `lang="en"`(UI는 전부 한국어).

## Overall Impression

**엔지니어링 도구로서의 뼈대는 좋다.** 워크플로가 상단 탭에 좌→우로 정직하게 배열돼 있고, 이번 사이클에 들어간 '해석 전 점검'은 이 앱에서 가장 잘 만든 화면이다. 무엇이 막고 있는지, 왜 막혔는지, 어디로 가야 고치는지를 한 카드 안에서 말한다. 다른 화면들이 이 수준이면 점수는 30점대다.

**가장 큰 문제는 라이트 모드가 사실상 깨져 있다는 것이다.** `palette(theme)` 토큰 체계는 잘 설계돼 있는데, 컴포넌트 128곳이 이를 우회해 다크 전용 네온 hex(`#37E08A`, `#FFC447`, `#FF5566`, `#90E8FF`)와 `rgba(0,0,0,0.18)` 스크림을 직접 박아 넣었다. 밝은 배경 위에서 이 색들은 읽히지 않는다. PRODUCT.md가 정의한 사용 환경이 "사무실 데스크탑, 밝은 실내 조명"인데 정작 밝은 테마가 못 쓰는 상태다.

## What's Working

1. **해석 전 점검(Analyze 탭)** — 흩어져 있던 판정을 한 곳에 모으고, 항목마다 상태·사유·힌트·이동 버튼을 준다. "해석 불가 — 1건 해결 필요" 요약 → "권상 그룹: 그룹 1: 0개(최소 2개)" → "Hoist 탭으로 ›". 사용자가 막힌 지점에서 다음 행동까지 가는 데 추측이 필요 없다.

2. **게이트 사유의 상시 노출** — 비활성 버튼이 왜 눌리지 않는지를 버튼 바로 아래에 적는다(`그룹 1: 0개 (최소 2개)`). 대부분의 사내 도구가 그냥 회색으로 죽여 놓는 지점이다.

3. **변환 감사 요약 chip** — 접힌 상태에서도 `2,310 전체 / 2,235 변환 / 75 제외 / 0 파싱실패 / 190 중복`이 남는다. 기본 접힘으로 바꾼 판단이 옳다. 화면 세로 36%를 상시 점유하던 표가 사라졌다.

## Priority Issues

### [P0] 라이트 모드 텍스트가 읽히지 않는다 — 대비 실패 52건

**Why it matters**: PRODUCT.md의 사용 환경은 "밝은 실내 조명"이고 접근성 기준에 "본문 ≥4.5:1"이 명시돼 있다. 실측 최악값은 **1.27:1**이다. Analyze 탭에서 `구속 노드 없음 — 권상 wire 가 유일한 지지입니다`(#90E8FF), `2,310행 중 265행이 변환되지 않았습니다`(#FFC447), `Edit 탭으로 ›` 버튼이 전부 배경에 묻힌다. **경고와 차단 사유가 안 보이는 것**이라 단순 미관 문제가 아니다.

실측 최악 목록: `ON` 배지 1.27:1 · `TOTAL MASS` 1.29 · `Studio` 워드마크 1.46 · COG `Y` 값 1.58 · 감사 chip `75 제외` 1.77 · `JSON 6/8개 로드` 2.01.

**Fix**: `PREFLIGHT_STATUS`, 감사 chip, 레이어 ON 배지, mass 오버레이의 하드코딩 hex를 `palette(theme)`의 의미론적 토큰으로 옮긴다. 팔레트에 `statusOk / statusWarn / statusDanger / statusInfo`를 라이트·다크 쌍으로 추가하고, `rgba(0,0,0,0.18)` 스크림은 `p.panelBg2`로 교체. 128개 하드코딩이 대상이다.

**Suggested command**: `/impeccable colorize`

### [P1] 타이포 위계가 없다 — 선언의 52%가 ≤10.5px

**Why it matters**: 폰트 크기 분포는 8px(8) · 9px(44) · 10px(87) · 11px(84) · 12px(42) · 13px(16) · 14px(5) · 15px(5) · **16px 이상은 전체에서 1개뿐**이다. 화면에서 무엇이 중요한지 크기가 말해 주지 않는다. `102.7 ton`(mass 오버레이)만 유일하게 크고, 정작 차단 사유·경고는 9~10px다. 8px 텍스트(`ON`/`OFF` 배지)는 데스크탑에서도 판독 한계다.

**Fix**: 4단 스케일로 정리 — 값/판정 15px, 항목 라벨 12.5px, 본문 12px, 메타 11px 하한. 8·9px은 전면 폐기. 위계는 크기 + 굵기로만 만들고 색은 상태에만 쓴다.

**Suggested command**: `/impeccable typeset`

### [P1] 상단 중앙에서 오버레이 3개가 겹친다

**Why it matters**: 스테이지 선택 `<select>`(전폭), 절차 스테퍼(플로팅), 권상 안내 토스트(플로팅)가 같은 좌표를 두고 싸운다. Hoist 탭에서 안내 토스트가 스테퍼의 3·4단계를 **가려 버리고**, Model 탭에서는 `파일 열기` 툴팁이 스테퍼와 스테이지 선택을 동시에 덮는다. 스크린샷 2·6번에서 재현된다.

또한 절차 스테퍼의 2·3·4단계가 모두 `mode: 'edit'`이라 Edit 탭에 들어가면 **세 단계가 동시에 활성 표시**된다. 지금 어느 단계인지 알 수 없다.

**Fix**: 스테이지 선택을 좌측 상단 고정폭(현재 전폭 1,180px을 짧은 라벨에 낭비)으로 줄이고, 스테퍼를 그 오른쪽에 같은 행으로 배치해 플로팅을 없앤다. 토스트는 하단 우측으로 이동. 2·3·4단계는 `tool` 기준으로 활성 판정(checkPlate / rbeConnect / mass)해 하나만 켜지게 한다.

**Suggested command**: `/impeccable layout`

### [P1] 좌측 독의 밀도가 탭마다 극단적으로 다르다

**Why it matters**: Model Check 탭은 항목 4개 뒤로 **700px 넘는 빈 공간**이 이어지고, Edit 탭은 7개 섹션 + 도움말 문단이 스크롤 밖으로 넘쳐 마지막 안내가 **문장 중간에 잘린다**(`부재 삭제: 3D 뷰포트에서 부재 클릭 → 외 선택된 부재 삭제…`). 같은 폭·같은 위치의 패널이 탭마다 완전히 다른 밀도를 가지면 사용자는 매번 다시 훑어야 한다.

더 실질적인 문제: **레이어 토글이 Model 탭에만 있다.** Model Check나 Edit에서 배관을 잠깐 끄고 보려면 Model 탭으로 돌아갔다 와야 한다. 검토 작업의 기본 동작이 탭 왕복을 요구한다.

**Fix**: 레이어 가시성을 탭 무관 공용 컨트롤로 승격(뷰 도구 패널에 통합). Edit 탭은 도움말 문단을 접이식 `?` 팝오버로 빼고 섹션을 아코디언화. Model Check의 빈 공간에는 그 탭에서 실제로 쓰는 컨트롤(레이어·간섭 목록)을 채운다.

**Suggested command**: `/impeccable distill`

### [P2] 컴포넌트 어휘가 한 패널 안에서 갈린다

**Why it matters**: Edit 탭 하나에 토글 표현이 3종이다 — 상태를 라벨에 넣은 버튼(`RBE 연결 모드 OFF`, `겹친 노드 구분 ON`), iOS 스타일 스위치(`표시`), 체크박스(`권상 리깅 검토`). `RBE 연결 모드 OFF`는 **현재 상태가 OFF라는 뜻인지 누르면 OFF가 된다는 뜻인지** 라벨만으로 판별할 수 없다. 레이어 목록은 또 별도로 `ON`/`OFF` 배지를 쓴다.

파괴적 동작 8곳이 네이티브 `window.confirm` / `window.alert`다. OS 대화상자가 튀어나오면서 시각 시스템이 끊기고, 버튼 라벨이 `확인/취소`로 고정돼 "무엇이 일어나는지"를 말하지 못한다. `SavePanel`의 `현재 model을 저장하고 Studio를 종료할까요?`는 **저장이 곧 종료**라는 중요한 결과를 취소 불가 네이티브 상자에 담고 있다.

**Fix**: 스위치 1종으로 통일하고 라벨은 상태가 아니라 대상만(`RBE 연결 모드` + 스위치). 네이티브 대화상자는 앱 내부 확인 패널로 교체하고 버튼은 동사+목적어(`저장하고 종료`, `삭제 의도 추가`).

**Suggested command**: `/impeccable clarify`

## 반응형 — 1280×720에서 세로 12%가 죽는다

`useResponsiveStudioScale`이 `scale(0.878)`을 걸지만 컨테이너 높이가 `720px`로 계산돼 렌더 높이가 632px에 그친다. **하단 88px이 빈 띠로 남는다**(실측). 1366×768에서도 같은 계산으로 약 49px이 낭비된다. 사내 노트북 해상도에서 흔한 조건이다. 게다가 전체 축소는 이미 8~10px인 텍스트를 7~9px로 더 줄인다.

`height: ${100/uiScale}%`가 부모 높이에 대해 의도대로 풀리지 않는 것이 원인. `height: calc(100% / var(--scale))` 또는 픽셀 계산으로 교체해야 한다.

- ❌ **Visual hierarchy** — 선언의 52%가 ≤10.5px, 16px 이상 1개
- ✅ One thing at a time — 상단 탭이 워크플로를 순차화
- ❌ **Minimal choices** — Model 탭 좌측 독에 레이어 9 + 모델 조작 3 + 초기화 = 13개 동시 노출
- ❌ **Working memory** — 레이어 상태를 Model 탭에서만 바꿀 수 있어 다른 탭에서 기억에 의존
- ✅ Progressive disclosure(부분) — 감사 dock 접힘은 개선. 단 Edit 탭은 7섹션 일괄 노출
