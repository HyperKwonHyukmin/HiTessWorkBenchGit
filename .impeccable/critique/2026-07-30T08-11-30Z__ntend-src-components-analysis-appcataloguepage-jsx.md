## 총평

**시각 품질은 확실히 올랐는데 총점이 그대로인 것이 이번 평가의 핵심이다.**

카드 자체는 다른 물건이 됐다. 정보 블록이 7개에서 4개로 줄었고, 제목이 제목으로 읽히고, 네이비 헤더가 사이드바·페이지 배너와 같은 언어를 쓰면서 카드가 프레임 안으로 들어왔다. `AppCard`는 341줄에서 248줄로 줄었다.

그런데 **1차에서 감점의 실제 원인이었던 것들은 대부분 손대지 않았다.** 개발 중 5장은 여전히 `opacity-60` 으로 흐려져 있고, 카테고리 탭은 여전히 8개이며, 즐겨찾기는 여전히 아무 일도 하지 않는다. 거기에 이번 작업이 **새 불일치를 하나 만들었다** — 그리드만 개편하고 리스트를 두면서 두 뷰가 서로 다른 물건이 됐다.

즉 남은 문제는 이제 시각이 아니라 **구조**다. 카드를 더 예쁘게 만들어도 점수는 오르지 않는다.

## 이번 작업이 실제로 개선한 것

1. **카드 정보 밀도** — Input칩/Output칩/태그 3줄 → `BDF → JSON XLSX 3D` 한 줄. 해석 앱의 본질(무엇을 넣으면 무엇이 나오는가)만 남겼고, 화살표는 `aria-hidden` + `sr-only` 문장으로 스크린리더 의미를 보존했다.
2. **타이포 위계** — 제목 15→18px, 칩·라벨 10px/900 → 11.5px/600·700. 가장 덜 중요한 텍스트가 제목보다 무겁던 역전을 해소했다.
3. **대비** — `slate-400`(2.9:1) → `slate-500`(4.76:1). 기여자·라벨·placeholder·뷰 토글·"관리자 전용" 전부. DESIGN.md 가 정한 하한을 이제 지킨다.
4. **브랜드 정합** — 헤더 그라데이션이 `PageHeader` 와 같은 문법(`from-brand-blue via-{accent}-900 to-{accent}-800`)이라 모드 정체성을 유지하면서 화면이 한 시스템으로 묶인다.
5. **Space 키 버그** — 카드에서 Space 가 앱을 열면서 동시에 페이지를 스크롤시키던 문제 해결(`AppCard` 한정).
6. **죽은 코드** — 액센트 맵 4종·`visualTone`/`cardDetailTone` prop 제거.

## 지금 상태의 문제

### [P1] 그리드와 리스트가 서로 다른 물건이 됐다 (신규·이번 작업이 만듦)

| | 그리드 카드 | 리스트 행 |
|---|---|---|
| 형식 표시 | `BDF → JSON XLSX 3D` 한 줄 | Input 칩 줄 + Output 칩 줄 |
| 태그 | 없음 | `트러스` `구조평가` 표시 |
| 헤더 | 네이비 그라데이션 | 없음(흰 행) |
| Space 키 | `preventDefault` 처리됨 | **여전히 페이지 스크롤** |

뷰 토글은 **밀도만** 바꿔야 하는데 지금은 정보량과 정체성까지 바뀐다. 같은 앱이 뷰에 따라 다른 물건으로 보인다.

**Fix**: `AppListRow` 에도 `FormatFlow` 를 쓰고 태그를 빼고 Space 처리를 맞춘다. `FormatFlow` 는 이미 별도 컴포넌트라 그대로 재사용하면 된다.

### [P1] '개발 중' 5장이 여전히 `opacity-60` 으로 흐려져 있다 (1차에서 이월)

카드 본문은 `slate-500`(4.76:1)인데 60% 불투명도가 곱해지면 실효 대비가 약 2.6:1로 떨어진다. 9개 중 5개, 화면 절반 이상이다. 1차 크리틱의 P1 이었고 사용자가 우선순위로 골랐으나 방향 전환으로 미착수 상태다.

**Fix**: 섹션을 기본 접힘(`개발 중 5개 ▾`)으로 두고, 펼쳤을 때는 흐림을 걷어내고 카드의 `개발중` 배지가 상태를 말하게 한다. 네이비 헤더가 도입되면서 흐림의 부작용이 더 커졌다 — 진한 헤더가 60%로 흐려지면 탁한 회청색이 된다.

### [P1] 카드가 여전히 버튼 안에 버튼을 품고 있다 (1차에서 이월)

`AppCard.jsx:119` 루트 `role="button"` 안에 즐겨찾기·설정 버튼이 있다. `AppListRow.jsx:67` 도 동일. Space 키만 고쳤고 중첩 구조는 그대로다. 스크린리더는 중첩 인터랙티브 요소를 예측 불가능하게 평탄화한다.

**Fix**: 루트를 `<article>` 로 두고 제목만 실제 `<button>` 으로 만든다(stretched-link 패턴).

### [P2] 네이비 헤더 9개가 3×3 으로 반복된다 (신규·이번 디자인의 대가)

카드 하나만 보면 좋지만, 9장이 모이면 **같은 크기의 진한 블록 9개**가 격자로 늘어선다. 시각적 무게가 커지고, 카드를 구별하는 단서는 여전히 제목 텍스트 하나뿐이다(아이콘·색은 File 모드 시그니처로 통일). 1차에서 지적한 "동일 카드 그리드의 반복"이 오히려 강조된 면이 있다.

**완화 방향** — 지금 구조를 유지하면서 쓸 수 있는 것:
- 헤더 세로 패딩을 `pt-6 pb-5` → `pt-5 pb-4` 로 줄여 네이비 면적을 축소
- 또는 활성 앱만 네이비 헤더, 개발 중 앱은 밝은 헤더로 두어 격자에 리듬을 만든다
- 또는 카드 폭을 넓혀 3열 → 2열로 (9개면 2열도 과하지 않다)

### [P2] 1차에서 이월된 구조 문제 (미착수)

- 카테고리 탭 8개 중 5개가 항목 1개 — 축이 섞여 있다(구조물 / 공정 / 파일형식)
- 즐겨찾기 별을 눌러도 이 페이지의 목록 순서는 그대로다
- 페이지 내 도움말·가이드 없음
