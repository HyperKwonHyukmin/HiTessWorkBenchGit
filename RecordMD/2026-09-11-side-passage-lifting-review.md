## 이번에 수정한 재현 오류

1. Studio `structuralSummaryView.js`: summary가 null이어도 clean 진단과 결합해 모든 부재 통과를 표시했다.
   - 평가 부재 수, 응력, 허용값이 없으면 판정 자료 부족으로 표시.
   - FATAL 결과는 오류 표시. 정상 문구도 '평가된 부재 응력'으로 범위 제한.
   - 누락된 초과/와이어 집계를 0으로 표시하지 않고 자료 없음으로 표시.
2. `StructuralResultSummary.jsx`: 결과에 허용값이 없어도 220 MPa로 범례가 표시됐다.
   - 결과에 기록된 유효 허용값만 사용. 경고 텍스트에 테마 색상 적용.
3. WorkBench `analysis.py`: 하중계수/허용응력의 `<= 0` 검사만으로 NaN/Infinity가 통과했다.
   - 유한한 양수 검사와 한국어 안내 추가.

검증: Studio 51파일 543테스트 통과, 수정 파일 ESLint 통과, Vite build 통과.
API 회귀검증 10건 통과(NaN/Infinity/음수/0, 두 입력 필드).
초기 화면 브라우저 확인 완료. 실모델 로드는 브라우저 파일 선택 도구가 거부해 수행하지 못함.
수정된 결과 화면의 실모델 시각 검증, 실제 Nastran 재해석, C# 엔진 검증 및 배포는 미완료.
기존 build 경고: useEditStore의 정적/동적 import 혼용.

## 사용자 협의가 필요한 새 기능

1. 통합 검증 요약: 입력 완전성 / 모델 연결 / 자세 안정성 / 리깅 SWL / 구조 응력 / 미검토 항목을 한 화면에 표시.
   '완료·적합·부적합·미평가·검토 필요'를 분리하고 각 행에서 근거와 해당 절점/부재로 이동.
2. 리깅 검증 강화: nominal/N-1 시나리오 구분, 힘·모멘트 잔차, 편중 적용 옵션, 슬링별 장비 허용값과 지배 조건.
3. 설계기준·하중조건 관리: 적용 기준과 버전, DAF/중량여유/CoG 허용범위/하중계수의 의미와 적용 위치를 기록.
   기존 Stage7의 DAF와 구조 해석 safety_factor가 어떤 하중에 각각 적용되는지 먼저 검증해야 함.
4. 인장전용/기하비선형 리깅 해석: 현재 SOL 101 압축 와이어 경고의 다음 단계.
   지원 Nastran 버전·라이선스와 적용 해법 검증이 필요하며, 슬랙 와이어 삭제만으로 자동 적합을 판정하지 않음.
5. 실행 기록·검토 보고서: 기존 보고서 재사용 여부 조사 후 원본/편집/해석 모델, 가정, 허용값, 지배 결과와 미검토 항목을 묶어 재현 가능하게 보관.
6. 부재 좌굴·러그/용접 상세 검토: 현재 응력 비교가 다루지 않는 검토 범위를 조사하고, 적용 규정과 상세 입력 확보 후 별도 구현.

추천 순서: 1과 2의 판정 의미/추적성 → 3과 5 → 검증된 요구에 따라 4와 6.
사용자 요청에 따라 신규 검증 기능과 공학 판정 기준 변경은 위 범위와 적용 기준을 협의한 뒤 착수한다.

## 승인 후 구현 및 검증 (2026-09-11)

사용자의 진행 승인에 따라 통합 검증 요약, 리깅 계산 근거, 실행 기록 보관을 구현했다.
설계기준·공학계수 변경과 비선형 해법 도입은 포함하지 않았다.

- Studio 저장 단계에 통합 검증 패널 추가. 입력 확인/해당 없음과 공학 적합을 구분하고, 부적합/검토 필요/미평가를 우선 표시한다. 각 항목에서 관련 단계로 이동한다.
- 부분 자세 결과, SWL 누락, 손상된 응력 집계, 실패 실행, 입력 변경 후 과거 결과는 적합으로 표시하지 않는다.
- C# Stage7은 SWL 미입력과 평형 검토 필요를 WARN으로 반환한다. 정상/N-1 시나리오별 수직 반력·힘/모멘트 잔차와 근사 여부, 슬링별 지배 시나리오를 출력한다. 상세 슬링 12개 제한을 제거했다.
- 평형 잔차의 1e-8은 정규화 수치 허용치이며 설계 허용기준이 아니다. 기존 편중계수 미반영 상태는 유지하고 화면/기록에 명시했다.
- 모델·편집·권상 조건과 질량 정보를 실행 시작 시 복사한다. 실행 중 옵션 변경, 실패 실행에서도 해당 실행 조건과 자세 근거를 보존한다.
- 검토 요약 Markdown과 전체 JSON을 각각 저장할 수 있다. 문서번호 메모는 계산 기준이나 승인을 변경하지 않는다.
- 백엔드는 결과 매핑 후 입력/편집/자세/해석 모델/F06/결과/브리지 스크립트 사본과 SHA-256 manifest를 실행별로 보관한다. 중복 기록은 덮어쓰지 않고, 보관 실패는 경고로 남긴다.
