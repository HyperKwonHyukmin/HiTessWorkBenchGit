# Module Unit 해상 운송 구조 해석 검토

## 2026-09-14 1차 보정 반영

- 배치 Z 회전을 GRID뿐 아니라 CBEAM/CBAR의 벡터 방향축·단부 오프셋과 CONM2 편심·관성텐서에 적용했다. G0 방향절점 방식은 이동된 GRID를 그대로 따른다.
- 응력 또는 용접 NG가 아니더라도 입력 불일치, 용접 결과 누락/오류, F06 수치 품질 경고가 있으면 종합 판정을 `검토 필요`로 표시한다.
- 특이 자유도의 상위 응력 영향권 밖이라는 이유만으로 전체 판정이 유효하다고 단정하던 문구를 제거했다.
- 결과 색맵 형상과 변위벡터에 실제 해석 배치의 회전·이동을 적용하고, 실행 ID/입력 변경 시 캐시를 분리한다.
- 지지점 상태 키를 충돌 가능한 `개수+합계`에서 정렬된 전체 인덱스 목록으로 바꿨다.
- 매 실행 산출물을 `ocean_runs/<job_id>/`에 보존하고 결과/DB 입력에 실행 ID와 전체 입력 스냅샷을 기록한다.
- 프론트엔드 폴링 제한을 약 6분에서 33분으로 늘려 백엔드 Nastran 제한(30분)보다 먼저 중단하지 않게 했다.

검증: 관련 백엔드 테스트 252개, 프론트엔드 유틸리티 테스트 106개, Vite 프로덕션 빌드 통과. 실제 Nastran 신규 실행과 인증 후 화면 육안 검증은 별도 운영 검증이 필요하다.

검토일: 2026-09-14. 현재 작업 트리의 소스, 관련 자동 테스트, 저장된 3521 해석 결과를 검토했다. 정확성·판정·시각화·이력 관련 1차 보정은 사용자 확인 후 반영했으며, 공학적 모델링 가정을 바꾸는 항목은 별도 협의 대상으로 남긴다.

## 결론과 적용 범위

정반과 Module Unit을 합본으로 풀고 같은 해에서 Unit 응력과 Leg 반력을 얻는 구조는 유용하다. 모델 배치와 결과 위치 확인, 용접 사양 재평가도 실무 지원에 도움이 된다. 그러나 현재 종합 OK를 운송 구조물 전체의 적합 판정으로 사용하는 것은 권하지 않는다. 회전 변환과 결과 갱신에 확인된 결함이 있고, 수치 신뢰도와 검토 범위를 종합 판정이 충분히 구분하지 못한다.

활용 범위는 승인된 하중·경계조건을 사용한 **제한된 선형탄성 응력 및 Leg 용접 검토**로 정의하는 것이 적절하다. 전체 운송 적합성을 말하려면 스툴·고박·정반·바지 갑판으로 이어지는 하중 전달 경로와 필요한 파괴모드의 검토 여부를 명시해야 한다.

## 실제 절차

1. BDF 업로드 → 공용 NastranBridge 기반 모델 파싱·입력 검증. Nastran 검증 실행은 선택 항목이다.
2. 정반 A/B 선택 → Module Unit 회전·XY 배치 → 지지점 선택 → 적치면·이격 확인 → 질량·무게중심 및 중량 여유 계산.
3. 사내 Barge 가속도 표에서 입력 조건과 LC1~LC4 중 한 조건을 계산한다. 중력을 포함한 총 가속도를 사용한다.
4. Unit의 기존 SPC·하중을 제거하고 ID를 재번호한다. 정반과 지지점을 RBE2로 연결하고 단일 GRAV, SOL 101로 해석한다.
5. Unit 부재 응력·변위, 정반 Leg 반력을 추출한다. 소구경 제외 기준을 적용하고 공통 용접 사양으로 Leg 용접을 평가한다.
6. 화면에서 OK/NG·색맵·변위·용접 상세를 확인하고 합본 BDF를 내려받는다. 용접 사양 변경은 저장된 반력으로 재평가한다.

이전 메모리와 다른 현재 사양: 최소 이격은 `module_ocean_merge.py:631`의 **100 mm**이다. 내부 부분 구속 RBE2에는 기본적으로 병진 123을 추가하고, 자유회전 방지를 위해 필요한 연결만 123456으로 승격한다. Unit-정반 지지 연결은 123456이다. 이전의 모든 RBE2 일괄 6자유도 설명은 현재 구현을 정확히 설명하지 못한다.

## 확인된 결함과 수정안

### 1. 회전 배치가 보 방향·편심 질량에 적용되지 않음 — 우선 수정

근거: `HiTessWorkBenchBackEnd/app/services/module_ocean_merge.py:305`, `place_grid_lines()`는 GRID만 변환한다.

최소 입력 재현: (0,0,0)→(1000,0,0) 보, 방향벡터 (0,1,0), CONM2 편심 (100,0,0)을 90도 돌렸다. 결과 GRID는 (0,0,0)→(0,1000,0)이 됐지만 방향벡터는 (0,1,0), 질량 편심은 (100,0,0)으로 남았다. 방향벡터가 보 축과 평행해지는 경우를 실제 함수 호출로 확인했다.

영향: 입력에 따라 solver 오류, 단면축 변경, 편심 방향 오류가 생길 수 있다. 저장된 모든 결과가 틀렸다고 단정할 수는 없으며, 사용 카드와 방향벡터를 기준으로 영향 모델을 선별해야 한다.

제안: GRID뿐 아니라 지원하는 CBAR/CBEAM 방향벡터·끝단 오프셋, CONM2 편심·관성 등 방향 의존 데이터를 일관되게 변환한다. G0 방식과 OFFT/CID 의미를 구분하고, 아직 처리할 수 없는 조합은 입력 단계에서 구체적으로 차단한다. 좌표계만 확인하는 현재 방어로는 부족하다.

검증: 비대칭 단면과 편심 질량 모델로 0/90/180/270도 변환, 역변환 및 하중도 함께 회전한 해석의 등가성 검증.

### 2. 용접 미평가·평형 불일치에도 종합 OK 가능 — 우선 수정

근거: `ModuleUnitOceanTransportAnalysis.jsx:190`의 배너는 `stress.exceedCount > 0`와 `weld.summary.status === 'NG'`만 합친다. 용접 결과가 없거나 오류 객체이면 weldNg는 false다. 배너는 반력 평형 검산을 전달받지 않는다. 지배 부재가 특이 영향권에 있어도 OK/NG 배지 자체는 유지한다.

제안: 수치 상태와 강도 판정을 분리한다. 최소한 `검토대기 / 검토보류 / 평가범위 내 OK / NG`를 구별하고, 필요한 결과 누락·검산 실패·미해결 특이·입력 변경에는 종합 OK를 내지 않는다. 오류 원인과 재평가/재해석 경로를 같은 위치에 표시한다.

### 3. 특이도 영향과 반력 타당성을 과도하게 단정 — 우선 수정

근거: `module_ocean_results.py:369`는 연결 그래프의 2홉과 응력 상위 요소로 특이 영향을 추정한다. 입력 그래프인 `module_ocean_bdf.py:243`는 선요소 중심이며 쉘/RBE2를 포함한 전체 강성 연결이 아니다. 프론트 `StressResultPanel`은 최대응력 부재가 그 범위 밖이면 “전체 판정은 유효”라고 표시한다. `OceanWeldPanel.jsx:256,486`은 반력 합계 통과 또는 평형 불일치 상황에서도 용접 판정 유효성을 단정한다.

판단: 그래프 거리는 진단 보조 수단이며 해의 정확성을 증명하지 못한다. 힘 합계가 맞아도 각 Leg의 분담과 모멘트가 맞는지는 별개다.

제안: 해당 단정 문구를 수정하고, 특이도·자동 구속·강체화 내역을 결과 신뢰도에 연결한다. 힘 3성분에 더해 공통 기준점의 모멘트 3성분을 검산한다. 필요 시 안정화 전후 민감도 및 독립 모델 비교를 수행한다. BAILOUT 유지/중단 정책은 진단용 실행과 설계 판정을 구별해 정한다.

### 4. 재해석 색맵이 이전 결과를 계속 사용할 수 있음 — 우선 수정

근거: `StressColorMapModal.jsx:40,79,97`은 elements/model이 비어 있을 때만 읽는다. 결과·모델 변경 시 이를 초기화하는 코드가 없다. 부모는 모달을 계속 마운트하며 해석별 key를 주지 않는다.

영향: 한번 색맵을 연 뒤 재해석하면 요약은 새 결과인데 색·변위·모델은 이전 값일 수 있다.

제안: 해석 ID와 모델 ID를 캐시 키로 사용하고 변경 시 데이터를 무효화한다. 늦게 도착한 이전 요청도 폐기한다. 동일 경로 덮어쓰기 구조와 함께 수정해야 한다.

### 5. 변형 형상의 좌표계 불일치 — 우선 수정

근거: 합본 해의 변위는 정반 전역좌표인데 `StressColorMapModal.jsx`는 원본 moduleModel을 사용한다. `stressColorMap.js:169`는 원본 positions에 t1/t2/t3를 그대로 더한다. 서비스는 ID만 되돌리고 변위 벡터를 역회전하지 않는다.

제안: 배치 후 전역 모델에 전역 변위를 적용하거나, 원본 모델에 회전의 역변환을 적용한 변위를 사용한다. 성분 색맵의 축 이름도 표시 좌표계와 일치시킨다. 합성 변위 크기는 회전에 불변이지만 형상의 방향은 그렇지 않다.

### 6. 입력 변경 후 예전 판정이 현재 조건처럼 보임 — 우선 수정

근거: 페이지의 material/배치/지지점/LC 변경은 structuralResult를 무효화하지 않는다. 조건 요약과 모델링 가정은 현재 입력으로 표시하며 결과는 이전 해의 값이다. 지지점 선택 무효화 키도 개수+합계라 서로 다른 선택 집합이 같은 키가 될 수 있다.

제안: 실행 입력 스냅샷과 편집 초안을 구별하고 `입력 변경됨 · 재해석 필요`를 표시한다. 과거 결과에는 과거 조건과 지지점을 사용한다. 선택 키는 정렬된 실제 절점 ID 전체로 만든다. 가속도 입력을 모델에서 가져온 경우 배치/중량 변경 시 재동기화 필요 상태도 표시한다.

### 7. 재해석 파일 덮어쓰기와 용접 재평가 이력 불일치 — 우선 수정

근거: `module_ocean_structural_service.py:290`의 산출 경로는 같은 업로드 폴더의 고정 stem이다. 페이지 `:2022`에는 이전 파일 소실 확인문이 이미 있다. `reassess_weld():134`는 용접 JSON을 덮어쓰지만 기존 DB result_info의 용접 요약은 갱신하지 않는다.

제안: 해석별 고유 하위 폴더와 입력·모델 해시를 사용한다. 지지점 ID, 제외 기준, 용접 사양, 가속도 출처, 엔진 버전을 기록한다. 용접 재평가는 원해석과 연결된 별도 revision으로 저장하고 화면·다운로드·이력이 같은 revision을 가리키게 한다.

### 8. 화면 추적은 약 6분, solver 허용은 30분 — 우선 수정

근거: 페이지 `usePolling`은 maxRetries=240, interval=1500 ms다. 요청 소요시간을 제외하면 약 6분이다. 백엔드 Nastran timeout은 1800초, 후처리는 별도 600초다. 폴링 오류 시 UI는 jobId와 전역 추적을 해제하지만 서버 작업이 끝났다는 보장은 없다.

제안: 경과시간과 서버 상태를 기준으로 추적하고 통신 끊김을 해석 실패와 구분한다. 재연결/상태 재확인과 결과 복구를 제공한다. 중복 제출로 같은 파일을 동시에 쓰는 상황도 고유 실행 경로로 방지한다.

### 9. 부분 결과 누락을 평가 완료로 볼 수 있음

근거: `evaluate_stress()`는 응력 없는 행을 버리고 한 요소라도 있으면 요약을 만든다. 응력 있는 요소 1개와 응력 필드가 None인 요소 1개를 넣은 재현에서 evaluatedCount=1, exceedCount=0을 반환했고 누락은 따로 표시하지 않았다. CROD/CTUBE 등 합본에 들어갈 수 있는 요소 유형도 현재 응력 집계의 지원 범위와 다르다.

제안: 예상 평가 요소 집합과 파싱된 결과 집합을 대조하여 누락/미지원/명시적 제외를 구분한다. 변위 누락, 비유한 값, solver 종료·결과 생성 시각도 확인한다. 결과가 없는 상태를 0이나 통과로 표시하지 않는다.

## 공학적 범위에 대한 사용자 결정이 필요한 항목

### 10. 실제 스툴·고박을 대표하는 모델

현재 스툴은 길이에 무관한 RBE2 강결이며 축력·전단·모멘트·인발을 전달한다(`module_ocean_merge.py:919`). 스툴 단면/재질/좌굴/접촉은 평가하지 않는다. 내부 RBE2도 자동 변경한다. 이를 실제 구조보다 항상 보수적이라고 단정할 수 없다. 강성·회전·인발 구속은 내력 분배와 안정성을 함께 바꾼다.

결정할 사항: 현장 연결이 용접 강결인지, 회전 허용 연결인지, 압축 접촉인지. 승인된 기존 강결 가정을 기본 프리셋으로 명시하고, 실제 스툴 CBEAM/CBUSH와 접촉/인발 검토를 도입할 범위를 정한다. 임의로 자유도를 풀거나 추가하는 UI보다 검증된 연결 프리셋과 명확한 물성 입력이 우선이다.

### 11. 하중조건 범위 및 가속도 적용 근거

현재 LC1~LC4 중 하나만 해석하고 +Y 조건만 정의되어 있다(`module_ocean_acceleration.py:45`). 비대칭 모델의 지배 부재와 Leg는 부호에 따라 달라질 수 있으므로 단일 결과로 전체 운송 포락을 대표할 수 없다.

제안: 우선 기존 LC1~LC4를 모두 실행·보존하고 부재/Leg별 지배 LC를 표시한다. 추가 −Y 조건과 조합계수는 승인된 운송 기준·원본 가속도 자료를 확인해 결정한다. 성분별 최대 반력을 임의로 합쳐 존재하지 않는 용접 하중조합을 만들지 않는다.

사내 Excel 표와 계산이 일치하는 것과 해당 바지·항로·계절·해상상태에 표가 적합한 것은 별도 검증이다. 화물 총중량은 정반+Unit인데 VCG는 Unit 기준으로 가져오는 현재 조합(`bargeAcceleration.js:103`)도 원본 표의 화물 정의와 대조해야 한다.

### 12. 강도·안정성 판정의 범위

현재 Unit 보 판정은 축력+굽힘 수직응력, 쉘은 von Mises를 단일 허용응력과 비교한다. 재료 이름은 SS275로 고정되고, 서로 다른 재료에 같은 입력 허용값을 적용한다. 전단·비틀림, 부재 좌굴/횡좌굴, 국부좌굴, 처짐 허용, 연결·스툴·정반·바지 갑판 강도는 종합 판정에 포함되지 않는다.

결정할 사항: 정반과 바지 갑판은 별도 승인 구조물로 취급할지, 앱 평가 범위에 포함할지. 부재의 설계 기준과 유효길이/횡지지 입력, 변위 허용기준을 정한 뒤 추가한다. 범위 밖 항목은 결과 첫 화면과 검토서에 표시한다.

### 13. 소구경 자동 제외와 용접 기준

현재 외경 기준만으로 관 단면을 배관 화물로 분류한다(`small_bore_element_ids`). 실제 구조용 소구경 튜브까지 제외할 수 있다. 제안: PID/그룹/용도 분류와 사용자 확인을 사용하고 제외 목록·근거·초과값을 보존한다.

용접 계산은 네 면 중앙 4분절의 8개 끝점에서 같은 Leg의 6성분 하중을 합성한다. 이는 유용한 탄성 수요 계산이지만 `yield/safetyFactor` 허용 기준이며 코드 기반 용접 저항식과 동일하지 않다. 공통 500×500 plate/268 mm 길이/10 mm 각장과 재료 450 MPa의 실물 적용 여부, 용접면과 반력 기준점의 일치, 모재·패드·갑판 국부파괴를 별도로 확인해야 한다.

### 14. 질량·평형 검산의 완결성

화면 질량 계산은 NSM과 CONM2 편심을 완전히 반영하지 않는다(`bdf_mass_properties.py:20`). 여유율은 MAT1 밀도와 CONM2 질량만 조정한다(`scale_mass`). 중량·CoG의 서버측 권위값과 실제 GRAV에 실린 질량을 대조해야 한다. 합계 힘 검산은 모멘트 검산을 대신하지 못하며 현재는 total_cog_mm가 모멘트 평형 계산에 사용되지 않는다.

제안: 지원 카드별 질량·CoG·단위 검증, WTMASS 정책, 6성분 평형 검산을 정리한다. 단위는 현재 mm–N–ton 기반임을 업로드 단계에서 명시한다.

## 모델링 제어와 UI/UX 개선

현재 장점: 지지점 단독 선택 화면, 박스 추가·해제, 초안 적용/되돌리기, 정반 투명화, 적치 실패 절점 표시, 회전 후보 비교, 가속도 범위 검증, 상세 용접 도식과 재평가가 있다.

제안:

- 지지점: 실제 절점 ID 검색·직접 입력·목록/3D 상호 강조, 선택 단계별 undo/redo, 지지점 세트 저장·불러오기. 현재는 그래픽 선택 중심이다.
- 배치: 회전·XY·스툴 높이·실제 연결 절점·수평 편심을 하나의 표에서 확인한다. 현재 스툴 그림은 수직선인데 해석 연결은 최근접 정반 절점까지 편심을 가질 수 있다.
- 결과: 완료 여부, 신뢰도, 강도 판정, 검토 제외 범위를 첫 화면에서 구분한다. 지배 부재·Leg를 누르면 해당 위치와 같은 LC의 내력을 표시한다.
- 용접: 1500px 최소폭/10px 글자 표는 요약 열과 상세 펼침으로 나누고 단위 N↔kN, N·mm↔kN·m 표시를 제공한다. `Case 1` 고정 표시는 실제 선택 LC로 바꾼다.
- 접근성: 상태 점에 텍스트를 붙이고, 토글/아이콘 버튼 이름과 모달 role·포커스 이동을 보완한다. 주요 숫자·입력 설명의 9~11px 글자를 조정한다.
- 검토 산출물: 입력 BDF·합본 BDF·F06·결과 JSON·배치 그림·하중조건·가정·제외 목록·품질진단·검토자 기록을 해석 ID로 묶어 저장한다.

UI 평가는 현재 코드 구조를 기준으로 한다. 브라우저는 `http://localhost:5173`에 연결했으나 로그인 화면까지 확인했다. 인증 후 실제 3D 화면, 좁은 창, 모달 조작과 콘솔 검증은 추가 수행해야 한다.

## 수행한 검증과 한계

- 해상 운송 관련 백엔드 테스트 8개 파일, 251개 테스트 통과(exit 0).
- 프론트 geometry/support/acceleration/reset/weld/stress 유틸 테스트 106개 통과.
- 회전 시 CBEAM 방향벡터·CONM2 편심 미변환을 최소 입력으로 재현했다.
- 부분 응력 누락이 별도 경고 없이 평가 집계에서 빠지는 것을 재현했다.
- 저장된 `20260908_141213_A476854_ModuleOceanMoving/3521_ocean_stress.json` 확인: 최대 180.365 MPa, 사용률 0.81984, 제외 167개, 고피벗 0. Leg 힘 합계 상대오차 2.607e-6. 용접 최대 114.909 MPa, 사용률 0.76606, 지배 Leg 2.
- 위 숫자는 **기존 저장 결과**다. 현재 코드로 새 Nastran 해석을 실행하거나 독립 구조검산으로 승인한 값이 아니다. 저장 결과의 회전은 90도이므로 방향 의존 카드 영향 확인도 필요하다.
- 자동 테스트는 코드 계약의 일관성을 확인한다. 모델링 가정의 실물 적합성과 누락된 파괴모드까지 검증하지 않는다.

## 권장 반영 순서

1. **결과 정확성 수정**: 회전 변환/변형 형상, 잘못된 종합 OK, 부분 결과 누락, 색맵 캐시, 입력 변경 표시, 실행별 파일 보존, 폴링 복구. 승인된 기존 허용기준을 바꾸지 않는 1차 패치로 묶는다.
2. **모델링·하중 사양 확정**: 실제 스툴·고박, LC 범위, 설계 기준, 정반·바지 평가 범위, 배관 제외 규칙. 결정된 항목별로 구현하고 기준 모델과 비교한다.
3. **실무 사용성**: 지지점 세트, 실행 비교, 결과 요약/상세, 검토 패키지 및 화면 검증.
