# DrawingToAnalysis — 사내 PDF DRM 우회(상호운용) 설명서

> **공유용 설명 문서.** WorkBench `DrawingToAnalysis` 앱이 사내 DRM/DLP 환경에서
> 도면 PDF를 어떻게 읽어 해석 모델로 변환하는지, 그 과정에서 사내 문서보안
> 소프트웨어의 자동 암호화를 **어떻게 우회(정확히는 상호운용)** 하는지
> 정리했습니다. **코드를 모르는 사람도 이해할 수 있도록 원리와 절차 중심으로**
> 설명합니다.

작성일: 2026-06-30
관련 1차 기록: [`drawing-to-analysis-pdf-drm-fix.md`](./drawing-to-analysis-pdf-drm-fix.md)

## 0. 한 줄 요약

> 사내 보안 프로그램이 **암호를 풀어주는 통로(우리 백엔드)** 로 도면을 받아,
> **깨끗한 표준 PDF로 다시 저장**한 뒤, **보안 프로그램이 다시 잠그지 않는
> 임시 장소**에 옮겨 두고 변환 엔진에 넘긴다. 그게 전부다.

---

## 1. 먼저: 여기서 말하는 "DRM"이 무엇인지

흔히 떠올리는 "유료 전자책·영화의 복제방지"가 **아니다.** 여기서의 DRM은
**회사가 자체적으로 깔아 둔 문서보안(DLP) 프로그램**이다.

- 이 프로그램은 컴퓨터 디스크에 저장되는 파일을 **자동으로 잠근다(암호화).**
  잠긴 파일은 겉모습이 일반 PDF와 달라져서, **그대로는 아무 프로그램도 열 수 없다.**
- 우리가 다루는 건 **회사 도면**이고, 변환 도구도 **회사 내부 도구**다.
  즉 *권한 있는 직원이, 회사 파일을, 회사 도구로* 처리하려는데
  **회사 보안 프로그램이 파일을 잠가버려 작업이 멈추는** 상황이다.
- 그래서 이 문서의 "우회"는 **암호를 깨는 행위가 아니다.** 회사 보안
  프로그램은 *허가된 프로그램에게는 잠금을 알아서 풀어준다.* 우리는 그
  허가된 통로로 받은 파일을 표준 형식으로 다시 저장할 뿐이다.

➡️ **정확히는 "암호 해독"이 아니라 "회사 보안 프로그램과의 상호운용"이다.**

---

## 2. 무엇이 문제였나 (증상)

도면 PDF를 올려 변환을 누르면 **"BDF 변환 실패"** 가 떴다.

겉으로는 멀쩡한 PDF인데, 변환 엔진이 "이건 PDF가 아니다"라며 멈췄다.
실패한 파일을 열어 보니 **앞부분이 정상 PDF 표시(`%PDF-`)가 아니라
회사 보안 프로그램의 잠금 표시(`HHIDRMC`)** 로 바뀌어 있었다.

---

## 3. 왜 그런 일이 생겼나 (핵심 원인)

여기엔 **"두 개의 프로그램이 같은 파일을 서로 다르게 본다"** 는 함정이 있다.

회사 보안 프로그램은 파일을 읽으려는 프로그램이 **허가 목록에 있느냐**에 따라
다르게 동작한다.

| 파일을 읽는 쪽 | 보안 허가 목록 | 실제로 보이는 것 |
|---|---|---|
| **WorkBench 백엔드(서버 프로그램)** | 허가됨 | **잠금이 풀린 정상 PDF** |
| **변환 엔진(별도 실행 파일)** | 미허가 | **잠긴 채로의 깨진 파일** |

여기에 더해, 보안 프로그램은 **특정 폴더(사용자 작업 폴더)에 저장되는 파일을
자동으로 다시 잠근다.** 그래서 백엔드가 모처럼 깨끗하게 만든 파일을 그 폴더에
두면, 변환 엔진이 읽기도 전에 **다시 잠겨버려** 또 실패했다.

또 하나의 함정: 단순히 "파일 앞부분이 `%PDF-`인가"만 보고 판단하면,
**겉은 잠긴 표시인데 실제로는 백엔드에서 잘 열리는 멀쩡한 파일**을 불량으로
오해하게 된다.

---

## 4. 해결 절차 (핵심 — 3단계)

문제를 세 가지 동작으로 풀었다. 순서가 중요하다.

### 1단계 — "허가된 통로"로 먼저 받아서 진짜 PDF인지 확인한다
변환 엔진(미허가)에게 바로 넘기지 않는다. **보안 프로그램이 잠금을 풀어주는
백엔드(허가됨)** 에서 파일을 먼저 연다.
- 파일 앞부분 표시(`%PDF-` 여부)만으로 판단하지 않는다.
- "백엔드에서 **실제로 열리느냐**"를 기준으로 유효한 PDF인지 판정한다.
  → 겉이 잠긴 표시여도 잘 열리면 정상으로 인정한다. (오해 방지)

### 2단계 — 잠겨 있으면 "빈 암호"로 한 번 열어준다
회사 보안으로 잠긴 도면은, 권한 있는 환경에서는 **암호 없이도 열리는** 경우가
많다. 그래서 빈 암호로 여는 시도를 한 번 한다.
- 이때도 끝내 못 열리는(진짜 비밀번호가 걸린) 파일만 실패로 처리한다.

### 3단계 — 깨끗한 표준 PDF로 다시 저장하고, "안 잠기는 장소"에 둔다
이 단계가 핵심이다. 한 번에 세 가지를 한다.
1. **표준 PDF로 다시 저장한다.** 잠금 잔재와 군더더기를 정리해
   누구나 여는 깨끗한 PDF로 만든다.
2. **저장 위치를 작업 폴더가 아니라 "임시 폴더"로 바꾼다.**
   임시 폴더는 보안 프로그램이 자동으로 다시 잠그지 않는 곳이라, 깨끗한
   상태가 유지된다.
3. 변환 엔진에는 **이 임시 폴더의 깨끗한 PDF**를 넘긴다.
   변환 결과물(해석 모델 등)은 원래대로 사용자 작업 폴더에 저장한다.

## 5. 전체 흐름 한눈에 보기

```
[직원이 도면 PDF 업로드]
        │
        ▼
사용자 작업 폴더에 저장됨
        │  (← 보안 프로그램이 여기서 파일을 자동으로 잠글 수 있음)
        │
        ▼
① 백엔드(허가된 통로)가 파일을 받아 "진짜 열리는 PDF인지" 확인
        │     · 겉표시 말고 실제로 열리느냐로 판단
        │     · 잠겨 있으면 빈 암호로 열어봄
        ▼
③ 깨끗한 표준 PDF로 다시 저장 → "안 잠기는 임시 폴더"에 둠
        │
        ▼
변환 엔진이 이 깨끗한 PDF를 읽음  → 정상 변환 성공
        │
        ▼
변환 결과물은 원래 작업 폴더에 저장 (사용자가 받는 위치는 그대로)
```

---

## 6. 왜 이게 "우회"이면서도 암호를 깨는 게 아닌가

- **잠금을 푸는 건 회사 보안 프로그램 자신이다.** 우리는 어떤 암호도 깨지 않는다.
  허가된 백엔드가 *이미 풀린 상태로* 받은 파일을 쓸 뿐이다.
- 우리가 한 "우회"의 실체는 단 두 가지다.
  1. 파일이 유효한지 **겉표시가 아니라 "실제로 열리느냐"** 로 판단했다.
  2. 변환 엔진에 줄 파일을 **보안 프로그램이 다시 잠그지 않는 임시 장소**에 두었다.
- 그래서 이건 **회사 보안 프로그램과 정상적으로 함께 동작하게 만든 것**이지,
  보호된 콘텐츠의 잠금을 부수는 행위가 아니다.

---

## 7. 결과 (검증)

- 다시 저장된 파일의 앞부분이 잠금 표시(`HHIDRMC`)에서 **정상 PDF 표시(`%PDF-`)** 로 돌아옴.
- 변환 엔진 정상 종료, 해석 모델(BDF)·뷰어용 데이터·미리보기 이미지 모두 생성됨.
- 화면(WorkBench)에서 올려도, 명령행에서 직접 돌려도 동일하게 성공 확인.

---

## 8. 같은 회사 환경의 "비슷한 회피책" (참고)

이 도면 변환 외에도, **같은 보안 프로그램 때문에 생긴 같은 종류의 문제**를
같은 원리로 푼 사례가 더 있다. 함께 알아두면 좋다.

1. **엑셀 내보내기** — 결과 표를 **디스크에 저장하지 않고 메모리에서 바로** 만들어
   내려준다. 디스크에 닿지 않으니 보안 프로그램이 잠글 틈이 없다.
2. **스튜디오 프로그램 다운로드(zip)** — 보안 프로그램이 디스크의 zip에
   **일정량을 덧붙여 잠그기** 때문에, 겉으로는 "손상된 파일"처럼 보인다.
   그래서 백엔드는 **잠금이 풀린 실제 내용 기준**으로 크기·검증값·다운로드를
   처리해, 사용자에게는 멀쩡한 파일이 가도록 했다.

**공통 원리**: *① 디스크에 표준 파일을 남기지 않거나(메모리/임시폴더),
② 허가된 통로가 받는 "잠금 풀린 실제 내용"을 기준으로 처리한다.*

---

## 9. 알아둘 점 / 주의

- **서버 반영**: 이 변경은 백엔드 코드라서, 운영 서버는 코드 갱신 후
  **백엔드를 재시작**해야 적용된다. (재시작 없이 떠 있으면 옛 동작 유지)
- **실패하면 어디부터 보나**: 백엔드에서는 열리는데 변환만 실패하면, 거의 항상
  "엔진에 넘긴 파일이 다시 잠겼다"가 원인이다. 진단 기록(`diagnostic.json`)에
  단계별 상태와 파일 앞부분 표시가 남으니 그것부터 확인한다.
- **전제 조건**: 이 방법은 **백엔드가 보안 허가 목록에 있다**는 전제에 의존한다.
  허가에서 빠지면 1단계의 "잠금이 풀려 들어온다"는 가정이 깨진다.
- **진짜 암호가 걸린 PDF**는 의도적으로 실패 처리한다. 이때는
  **원본이나 잠금 해제본을 다시 업로드**해야 한다.
- **적용 범위**: 이 문서는 **회사 도면 + 회사 도구 + 회사 보안 프로그램** 환경의
  내부 운영 기록이다. 외부·제3자의 보호 콘텐츠에는 해당하지 않으며 적용해서도 안 된다.
